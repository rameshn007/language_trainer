# Language Trainer — Project Guide

European Portuguese learning app for English speakers (iOS/Android).
Flutter 3.47.6 · Dart SDK `^3.10.7` (`pubspec.yaml` `environment.sdk`) · Riverpod (`Notifier`/`NotifierProvider`) · Hive local storage · `just_audio` + `just_audio_background` + `audio_session` · `flutter_carplay` 1.6.2.
No backend: TTS, STT and quiz generation run on-device.

## Layout

- `lib/main.dart` — only the cross-cutting providers live here: `storageServiceProvider`, `ttsServiceProvider`, `notificationServiceProvider`, `navigatorKey` (notification deep links). Everything else is declared beside its own class: `progressServiceProvider` (`progress_service.dart`), `verbServiceProvider` (`verb_service.dart`), `listenRepeatContentServiceProvider` + `listenRepeatModeCountsProvider` (`listen_repeat_content_service.dart`), `translationServiceProvider`, `relatedWordsServiceProvider`, and the feature state in `lib/ui/*/…_view_model.dart` (`listenRepeatViewModelProvider`, `quizViewModelProvider`, `exerciseViewModelProvider`, `verbConjugationViewModelProvider`, `singleVerbConjugationViewModelProvider`). Grep for `Provider =` rather than assuming `main.dart`.
- `lib/services/` — one class per file (audio: `tts_service`, `silence_audio_service`, `carplay_service`; quiz: `quiz_engine_service`, `voice_quiz_service`, `question_loader_service`; content/state: the rest). `lib/ui/*/…_view_model.dart` holds feature state.
- `lib/ui/` — imperative `Navigator.push` + `CircularRevealClipper`, no named routes; `HomeScreen` is root.
- `lib/ui/flashcards/` — `FlashcardsScreen` (filtered deck + hands-free auto-advance chain) with `widgets/flashcard_card_widget.dart` and `widgets/conjugation_table_widget.dart`. Deck defaults to **shuffled + auto-advance on**; decks injectable via `initialCards`.
- `lib/utils/iphone_duo_helper.dart` — single source of truth for iPhone Duo / Dynamic Island geometry: `isDuo`, `systemIconReservedWidth` (76), `appBarActionsRightPadding` (56), `getContentHorizontalPadding`, `getAppBarActionsRightPadding`, `getFabLocation`, `debugOverride`.
- Data loading is staged, not all at launch. `HomeScreen` reads at startup: `assets/vocabulary.json` (871 entries), `assets/data/source.md`, `assets/Combined_Portuguese_Class_Notes.md`, `assets/data/verbs.csv`. Everything else loads when the feature opens: a Listen & Repeat session start pulls `a2_topic_words.json`, `phrases.json`, `verb_phrases.json`, `prepositions.json` and the `vocabulary.json` example sentences (`listen_repeat_content_service.dart`); a quiz/exercise start pulls `questions.json`, `combined_questions.json`, `grammar_rules.json`, `interrogatives.json`, `prepositions.json` or the named `exercises/*.json` (`question_loader_service.dart`); the flashcard deck build pulls `grammar_flashcards.json` (7 cards) + `vocabulary.json`. `pubspec.yaml` declares `assets/data/` and `assets/data/exercises/` as two entries because dir declarations are not recursive — dropping the second silently 404s every exercise file. Only 4 hint PNGs are live (`assets/images/unit_2..5_hint.png`, passed as `hintPath`); `home_illustration.png` is referenced by nothing and `app_icon*.png` are `flutter_launcher_icons` build inputs, not runtime loads.
- Dead data that looks live. The live vocabulary source of truth is `assets/data/source.md`. Read by nothing at runtime: the 211-line `source.md` at the repo root, the other root dumps (`Even_More_words.md`, `new.md`, `new_words_2.md`, `more_words_1.md`, `mon_mar_9_words.md`, `batch_1.md`, `extracted_words.json`), and the undeclared `assets/` files (`ano_words_phrases.md`, `new_words_phrases.md`, `European_Portuguese_Grammar_Cheat_Sheet.md`, `Questions *.rtf`, the screenshots). `assets/data/inbox.md` *is* bundled (it sits inside a declared dir) while only `scripts/ingest_inbox.py` ever reads it. Never edit a root dump as if it were content.
- Data tooling. Supported entry points: `scripts/ingest_inbox.py` (moves inbox items into `source.md` **and empties `assets/data/inbox.md`** — commit or copy the inbox first), `scripts/sanitize_source.py`, `scripts/check_duplicates.py`, `check_translations.py` (root, read-only: reports rows missing English), and `generate_quiz.py` (appends by default; `--rebuild-all` wipes `questions.json` and re-keys every id, breaking `seen_questions` and mastery history). Everything else ending in `.py` is a spent one-shot that rewrites live data in place and would duplicate or corrupt content on a second run: at the repo root `add_content.py` (rewrites `phrases.json` + `exercises/prepositional_pronouns.json`), `append_vocab.py`, `sanitize_data.py`, `process_ano_words.py`, `process_new_words.py`, plus `fix_prints.py` / `fix_home_screen.py` which overwrite `listen_repeat_view_model.dart` / `home_screen.dart` wholesale; in `scripts/` `ingest_ano_words.py` (rewrites `assets/ano_words_phrases.md` + `source.md`), `ingest_classes_6_7.py`, `massive_expansion.py`, `process_new_words.py`, `append_new_questions.py`, `add_a2_topics_exercises.py`, `add_listen_repeat_phrases.py`. The relative-path ones (`massive_expansion.py`, `scripts/process_new_words.py`, `append_new_questions.py`, `ingest_classes_6_7.py`) only behave correctly from the repo root, and `massive_expansion.py` / `process_new_words.py` still find their `extracted_words.json` input, so they do run — that is why they are listed. Of the rest of `scripts/`, `increment_build.py` is live tooling invoked by `deploy-build-ios.sh`; `generate_screenshots.py` is screenshot tooling.

## Invariants (break these and failures are silent)

- Hive typeIds frozen: `LanguageItem`=0, `QuestionType`=1, `Question`=2. Append fields, never renumber.
- Mastery: `LanguageItem.masteryLevel` 0–5; display tiers 0–4 New/Learning/Familiar/Strong/Mastered (`progress_data.dart`, `maxTier = 4`).
- XP: 10 first correct / 5 retry (`storage_service.dart` `updateWordProgress`), +20 session completion, +10 daily-goal bonus, default goal 50 XP/day (`progress_service.dart`).
- Quiz: 8 `QuestionType` values (`lib/models/question.dart`); seen questions persist in the `seen_questions` box, so any new type must register there or it repeats.
- Voice grading (`voice_quiz_service.dart`): exact → substring → Levenshtein fuzzy at >0.65 similarity; keep all three tiers.
- Speech recognition lives only in `voice_quiz_service.dart` (`SpeechToText`), which only `lib/ui/voice_trainer_screen.dart` instantiates; quiz and exercise screens have no mic. A "voice recognition fails in the quiz" report is a Voice Trainer report.
- Listen & Repeat and CarPlay share one audio session. Mode switch / reshuffle pass `recordProgress: false`; only an explicit stop awards XP (blocks XP farming).
- Every `AudioSource` needs a `MediaItem` tag with unique id (`'${item.id}_...'`) or lock-screen/CarPlay notification breaks.
- The 6-source word layout is hard-coded outside the constant: `test/listen_repeat_remote_control_test.dart` asserts `sources.length == 6` and `seek(Duration.zero, index: 6)`. Changing `_kSourcesPerWord` means editing those literals and the `AppDelegate.swift` doc block too — native code does no seek math of its own, it forwards `remoteNextWord` / `remotePreviousWord` to Dart.
- Flashcard answers pay XP through `ProgressService.recordQuizAnswer` — never `updateWordProgress` alone (that moves mastery but awards no XP).
- Session +20 is gated on `_hasAwardedCompletionThisPass && _cardsStudiedThisPass.isNotEmpty`; both reset on restart/deck rebuild. Keep that pairing — a completion bonus keyed only to a once-per-screen flag is farmable with two gestures.
- Flashcard auto-advance chain = one `AnimationController` (`_countdownController.forward().orCancel`, catch `TickerCanceled`) + `_speechDelayTimer`/`_speechDelayCompleter` + per-chain `_speechChainToken`. Every await between utterances must re-check `token == _speechChainToken && mounted && !_isDisposed`; `_stopSpeech` bumps the token, kills the timer **and** completes the pending completer (a hanging completer parks the chain forever).
- Anything indexing `_deck[_currentIndex]` needs a `_deck.isNotEmpty` guard (empty deck + auto-advance threw `RangeError (length): Valid value range is empty: 0`).
- Status strip and countdown bar sit outside the card body and listen to `_countdownController` via `AnimatedBuilder`; don't rebuild the card body per frame. A content-rich card is ~21 s of audio + reading time — budget new spoken segments accordingly (the 878-card deck — 871 vocab + 7 grammar cards — is not meant to auto-play end to end; filtered decks are).
- Deck shuffle is unseeded `List.shuffle()` and auto-advance defaults on → pass `initialShuffle: false` / `initialAutoAdvance: false` in tests unless that path is the subject.

## Landscape / iPhone Duo layout (failures are visual, portrait tests won't catch them)

- Take horizontal insets from `IPhoneDuoHelper.getContentHorizontalPadding(context, hasFab: false)` — pass `hasFab: false` on screens with no FAB (Flashcards); the default adds +84 right clearance for the FAB. AppBar actions take `getAppBarActionsRightPadding(context)`.
- Never stack manual horizontal padding on top of an active horizontal `SafeArea`: `SafeArea` re-applies `MediaQuery.padding.right`, so the insets add up (bottom bar once measured 88 pt against the card's 44). Either let `SafeArea` do it, or use `SafeArea(top: false, left: false, right: false)` plus helper padding.
- The left edge needs the same treatment as the right: in island-left landscape the system band is 44–59 pt, so fixed 18–20 pt padding puts content under the cutout.
- Keep card content and the bottom control bar on the same inset — misalignment between the two reads as a bug even when nothing overflows.
- Home tile grids are content-driven, not breakpoint-driven: `chooseTileColumnCount` (`lib/ui/home_tile_layout.dart`) measures the section's copy and takes the widest grid that fits it, so a phone renders one full-width tile per row. Tile text sits in a `FittedBox(fit: scaleDown)`, and `RenderFittedBox` lays its child out *unbounded* — a column too narrow for the copy never ellipsizes it, it just paints the text smaller (the old 2-column phone grid rendered tile text at 40–70% of its `fontSize`). Type sizes, chrome width and the column floor live in that file; `test/home_tile_layout_test.dart` pins the rule.
- Two pairings keep tile measurement and paint agreeing, and both broke silently once: the tile's `TextStyle`s state `height: tileLineHeight` instead of inheriting the theme's `bodyMedium` (also 1.43 — a bare style measured ~43% shorter than it painted, so big system text got shrunk), and the text scaler is applied on exactly one side (`measureTileTextBlock` pre-scales its font sizes with `TextPainter` at `noScaling`, so the `Text` widgets must pass *design* sizes and let `MediaQuery.textScaler` scale them once). A 2- or 3-column section pads a short last row with empty `Expanded` slots: an odd row without them stretches across the grid.

## Test harness gotchas

- `tester.pump(Duration(n))` advances the fake clock in a **single** frame. `AnimationController`/countdown sequences need repeated small pumps (16–250 ms) to actually run.
- `rootBundle.loadString` does not resolve asset paths under fake async, so the production deck-load path is not widget-testable — inject decks with `initialCards`.
- mocktail needs `registerFallbackValue` for `SessionRecord` and `ActivityType` when mocking storage/progress.
- Device geometry comes from `tester.view.physicalSize` / `devicePixelRatio` / `padding` / `viewPadding` (`configureDevice` in `test/iphone_landscape_layout_test.dart`); Duo detection is forced with `IPhoneDuoHelper.debugOverride`.
- Shared audio/CarPlay mocks (`MockAudioPlayer`, `MockListenRepeatContentService`, `MockTtsService`, `MockProgressService`) live in `test/helpers/carplay_test_helpers.dart` — 10 suites import it, including the layout suite. Put new fixtures there rather than re-declaring per file.

## Deep dives (read only when the task touches them)

- `.agents/skills/listen-repeat-audio/SKILL.md` — 6-source word layout including the duplicated-PT-file rule, buffer/starvation/speech-shielding contract, TTS concurrency, and where the skip math actually lives.
- `.agents/skills/carplay-integration/SKILL.md` — scene gating and its 2 s dedupe, 8-row template limit, Now Playing star + artwork, IPC debouncing, steering-wheel remote commands.
- `.agents/skills/expand-vocabulary/SKILL.md` — inbox → `source.md` → `questions.json` pipeline, which scripts are safe to re-run, which tests read the data files.

## Verify before finishing

- `flutter test` — all must pass (494 tests in 32 files as of Oct 2026; the count drifts, trust the run over this line) · `flutter analyze` — zero issues · `flutter build ios --no-codesign --simulator` for native changes.
- Run the suite twice when touching flashcards or layout: unseeded deck shuffle and audio pacing are non-deterministic, so one green run proves less than it looks like.
- CarPlay/audio tests need `CarPlayService().resetForTesting()` in `tearDown` (cancels section-update timers, container subscriptions, debounce timestamps).
- Any test that sets `IPhoneDuoHelper.debugOverride` must reset it (`IPhoneDuoHelper.resetForTesting()`, e.g. in `addTearDown`), or the override leaks into later layout tests; also reset `tester.view` size/padding after changing it.
